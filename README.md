# Health AI Copilot

面向医疗健康场景的 **患者教育与风险分流原型**。它的目标是把经过审核的公开医学资料转成可追溯、可评测的回答，并把高风险问题明确分流给人工或线下就医渠道。

> 本项目是技术原型：不接入真实患者数据，不提供诊断、处方或医疗建议，不作为互联网诊疗系统使用。

## 为什么做这个项目

这个题目同时能展示互联网 AI 岗位关心的能力：RAG、Agent harness、离线评测、可观测性、提示词防护、人工审核闭环，以及上线前的数据/安全边界设计。

## 范围

| 包含 | 明确不包含 |
| --- | --- |
| 公开指南的患者教育问答 | 诊断、处方、治疗决策 |
| 红旗症状识别与就医提示 | 真实患者病历和影像 |
| 有来源引用的检索生成 | HIS/EMR/医保/挂号/支付对接 |
| 人工审核队列的原型接口 | 医生身份认证和线上问诊 |

## 开发路线

1. `M0`：完成资料卡、知识库导入、回答必须带引用。
2. `M1`：加入风险分流和拒答/转人工策略。
3. `M2`：构建离线评测集，跑检索、引用、风险与安全指标。
4. `M3`：加入审核队列、反馈数据集与可观测性。
5. `M4`：用合规的离线数据做 SFT/偏好优化实验，仅比较原型能力。

详细架构和知识点见 [docs/architecture.md](docs/architecture.md)、[docs/roadmap.md](docs/roadmap.md) 与 [docs/post-training.md](docs/post-training.md)。

## 快速开始

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -e ".[dev]"
pytest
```

当前代码仅实现了可测试的安全网关骨架；模型、向量库与模型供应商应通过环境变量配置，绝不提交密钥或真实数据。
