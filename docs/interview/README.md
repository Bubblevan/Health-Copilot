# 面试准备文档

这组文档服务于同一件事：把 Health-Copilot 的面试回答绑定到可以回到仓库核对的事实，而不是背一份技术名词清单。

## 两份文档的边界

- [project.md](project.md)：只写 Health-Copilot 在基线 commit ac1b2ac8e63c0e1476f992c159b40b5bf39e4d06 上真实存在的 M0 行为、源码、测试、评测数字、失败案例和迭代方向。尚未合并的 Agent Core 统一标为 [M1 PLANNED]。
- [bagua.md](bagua.md)：独立的 Agent / LLM / RAG / 推理 / 后训练面试知识地图。它可以解释当前项目没有使用的通用概念，但不会把这些概念写成 Health-Copilot 已实现的能力。

## 推荐阅读路径

1. 先读 project.md 的开头 30 秒回答，再沿着“项目是什么 → 请求怎么走 → 为什么这样设计 → 哪里失败 → 如何验证 → 下一步”的 Q1–Q43 顺序练习。
2. 面试官从项目事实跳到通用概念时，再打开 bagua.md 对应的主题；每个主题都按“短答 → 原理 → 公式/数量级 → trade-off → 追问”组织。
3. 需要核对事实时，优先回到文档中列出的源码、测试和 evals/ 文件；参考链接只用于通用技术概念，不替代项目证据。

## 标记含义

- [M0 已实现]：在当前基线源码中可以直接找到实现，并且通常有测试或评测证据。
- [M1 PLANNED]：路线图中的下一阶段设计，当前基线没有实现，不能作为简历中的已完成能力。
- [通用知识]：与项目实现状态解耦的面试知识；是否使用过，仍要回到 project.md 判断。
